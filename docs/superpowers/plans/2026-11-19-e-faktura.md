# e-Faktura, ulazne fakture iz SEF-a (0.15.0): plan implementacije

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Cilj:** Odeljak „e-Faktura“: ulazne fakture sa SEF-a na telefonu, prihvatanje više faktura odjednom, slanje prihvaćenih jednim mejlom i trajna istorija. Sve radi na probnom SEF-u dok se pravi ne uključi.

**Arhitektura:**
- Telefon zove samo `api/efaktura.js` (jedna Vercel funkcija, polje `action`).
- Server proverava Supabase sesiju i dešifruje SEF ključ iz `efaktura_settings`. Zatim zove pravi SEF (`sefClient.js`) ili probni (`sefMock.js`), istoriju piše u `efaktura_events` i šalje mejl preko Resend-a.
- Logika je u čistim modulima u `src/lib/` (`efakturaActions.js` je srce), testiranim sa skladištem u memoriji. Isto skladište i probni SEF služe `npm run dev` preko Vite middleware-a.

**Tehnologije:** React 18, React Router 7, Supabase JS, Resend, `node:crypto` (AES-256-GCM), Vitest + jsdom.

**Spec:** [`2026-11-17-brancode-e-faktura-design.md`](../specs/2026-11-17-brancode-e-faktura-design.md). Zvanična SEF specifikacija: `https://efaktura.mfin.gov.rs/swagger/public_v1/swagger.json`.

**Grana:** `e-faktura`. Na `main` ide jedan squash commit, verzija 0.15.0, posle testova i pregleda.

## Globalna ograničenja

**Moduli**
- **Klijent uvozi samo dva modula:** `efakturaRules.js` i `efaktura.js`. Svi ostali e-Faktura moduli su za server i dev (`efakturaCrypto`, `sefClient`, `sefMock`, `efakturaStore`, `efakturaMemoryStore`, `efakturaMail`, `efakturaActions`, `efakturaHandler`), i klijentski kod ih ne uvozi ni posredno.
- **`node:` moduli** su dozvoljeni samo u `efakturaCrypto.js`.

**Režimi i ključ**
- **Režimi:** `SEF_ENV` = `production` | `demo`; sve drugo, i prazno, je `mock`. `npm run dev` je uvek `mock`.
- **Adrese:** production `https://efaktura.mfin.gov.rs`, demo `https://demoefaktura.mfin.gov.rs`. Nikad ne dolaze od klijenta.
- **Prekidač za prihvatanje:** prihvatanje i odbijanje rade u `mock` uvek, a u `demo`/`production` samo uz `SEF_ACCEPT=on`; inače server vraća `accept-disabled`.
- **Šifra:** `EFAKTURA_SECRET` je base64 od tačno 32 bajta. U `mock` bez nje važi ugrađena probna šifra `MOCK_SECRET`; u `demo`/`production` bez nje je `not-configured`.
- **Ključ se ne odaje:** nikad nije u odgovoru, u logu ni u poruci greške. Klijent vidi samo `keyLast4`.

**Ograničenja SEF-a i obima**
- **SEF:** najviše jedan poziv na 340 ms u jednom zahtevu. Na 429 server čeka 1000 ms i ponavlja jednom. Zaglavlje je `ApiKey`.
- **Brojevi:** prozor `WINDOW_DAYS = 60`, rok za odgovor `RESPONSE_DAYS = 15`, istaknut na `URGENT_DAYS = 3`. Najviše 50 faktura po pozivu za `accept`/`send`. Razlog odbijanja je 1–500 znakova posle `trim`. Naziv radnje je 1–100 znakova. PIB je `/^\d{9}$/`. Mejl ima najviše `MAX_MAIL_BYTES = 25 * 1024 * 1024` sirovih bajtova priloga.
- **Datumi:** za grupisanje po danu i „danas“ važi Europe/Belgrade.

**Tipovi koje koriste svi zadaci**
- **`Invoice`:** `{ id: number, number: string, supplier: string, supplierPib: string|null, amount: number, amountWithoutVat: number|null, vat: number|null, currency: string, status: string, receivedAt: string /* ISO */, dueDate: string|null /* YYYY-MM-DD */, send: SendInfo|null, decision: Decision|null }`.
- **`SendInfo`:** `{ state: "unsent"|"sent"|"before", lastSentAt: string|null, lastSentTo: string|null }`.
- **`Decision`:** `{ action: "accepted"|"rejected", userEmail: string, at: string, comment: string|null }`.
- **`SefApi`:** `{ checkKey(): Promise<void>, overview({ dateFrom: Date, dateTo: Date }): Promise<Invoice[]>, acceptReject({ invoiceId, accepted, comment }): Promise<{ success: boolean, message: string|null }>, invoiceStatus(invoiceId): Promise<string>, pdf(invoiceId): Promise<Uint8Array> }`. Greške su `SefError` sa `code` = `key-rejected` | `sef-unavailable` | `sef-error`.

**Kodovi grešaka** (`{ ok: false, error }`):

| Status | Kodovi |
|---|---|
| 400 | `bad-action`, `invalid-ids`, `too-many`, `invalid-comment`, `invalid-shop-name`, `invalid-pib`, `missing-key`, `not-mock` |
| 401 | `missing-token`, `invalid-token` |
| 403 | `accept-disabled` |
| 405 | `method-not-allowed` |
| 409 | `not-connected` |
| 413 | `pdf-too-large` |
| 500 | `not-configured`, `server-error` |
| 502 | `key-rejected`, `sef-unavailable`, `sef-error`, `send-failed` |

### Task 3: Pravi SEF klijent

**Fajlovi:** Create `src/lib/sefClient.js`, `src/lib/sefClient.test.js`.

**Consumes:** tipovi `Invoice`, `SefApi` i `SefError` iz Globalnih ograničenja.

**Produces:**
- `SEF_BASE_URLS = { production, demo }`.
- `class SefError extends Error`, sa `code` i opcionim `httpStatus`. Poruka je `` `SEF ${code}${httpStatus ? ` (${httpStatus})` : ""}` ``, a `detail` je najviše 200 znakova tela odgovora. Ni poruka ni `detail` nikad ne sadrže ključ ni URL sa ključem.
- `normalizeInvoice(dto) → Invoice | null`:
  - vraća `null` bez `invoiceId`;
  - `number` je `documentNumber ?? ""`, `supplier` je `supplierName ?? ""`;
  - `supplierPib` je `supplierVatRegistrationNumber ?? supplierRegistrationNumber ?? null`;
  - `amount` je `Number(amount)`;
  - `currency` je `currency || "RSD"`;
  - `status` ostaje kakav je ako je poznat, inače `"Unknown"`;
  - `receivedAt` je `sentDate`;
  - `dueDate` je prvih 10 znakova od `dueDate`, ili `null`;
  - `send` i `decision` su `null`.
- `createSefClient({ baseUrl, apiKey, fetch = globalThis.fetch, sleep, now = Date.now, minGapMs = 340, timeoutMs = 20000 }) → SefApi`:

  | Metod | Poziv | Napomena |
  |---|---|---|
  | `checkKey` | `GET /api/publicApi/getEfakturaVersion` | |
  | `overview` | `GET /api/publicApi/purchase-invoice/overview?dateFrom=…&dateTo=…` | ISO; na odgovor 400 po jedan poziv za svaki status iz `["New","Seen","ReNotified","Approved","Rejected","Storno"]` (`&status=`), spojeno bez duplikata po `id` |
  | `acceptReject` | `POST /api/publicApi/purchase-invoice/acceptRejectPurchaseInvoice` | telo `{ invoiceId, accepted, comment }`; `success` je `true` samo kad je u telu baš `success === true`; neparsirljivo telo daje `{ success: false, message: null }` |
  | `invoiceStatus` | `GET /api/publicApi/purchase-invoice?invoiceId=` | vraća `.status` |
  | `pdf` | `GET /api/publicApi/purchase-invoice/pdf?invoiceId=` | bajtovi |

  - Svaki poziv šalje `ApiKey`.
  - Između poziva čeka najmanje `minGapMs`.
  - 401 i 403 daju `key-rejected`.
  - 429 se ponavlja jednom posle 1000 ms; drugi 429 daje `sef-unavailable`.
  - 5xx, mrežna greška i istek vremena (AbortController) daju `sef-unavailable`.
  - Ostali odgovori koji nisu ok daju `sef-error`.

- [ ] **Testovi (crveni)**, sa lažnim `fetch`, `sleep` i `now` koji beleže pozive:
  - `sends the ApiKey header to the configured base url`;
  - `waits at least 340 ms between calls`;
  - `retries once after 429`;
  - `gives sef-unavailable after a second 429`;
  - `maps 401 and 403 to key-rejected`;
  - `maps a network error and a timeout to sef-unavailable`;
  - `falls back to one overview call per status on 400 and merges by id`;
  - `counts acceptReject as success only for success === true` (slučajevi: `success: true`, `false`, polje nedostaje, telo nije JSON);
  - `normalizeInvoice` (bez id, nepoznat status, `dueDate` skraćen, prazna valuta daje RSD);
  - Review Focus 5: `never puts the key in an error` — `fetch` baca `new Error("boom https://x?ApiKey=TAJNI")`, a `JSON.stringify` greške, `message`, `detail` i `stack` ne sadrže `TAJNI`.
- [ ] Pokreni `npx vitest run src/lib/sefClient.test.js`. Očekivano: FAIL.
